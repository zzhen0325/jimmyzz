# 本地与线上内容合并

代码部署与内容发布已拆分：`npm run deploy:cloudflare` 只部署代码，不再自动覆盖 R2 内容。

## 常用命令

```sh
# 读取线上快照，生成合并预览，不改写本地或线上内容
npm run sync:content

# 将无冲突结果写回本地，并下载线上独有的引用媒体；不发布
npm run sync:content -- --write-local

# 将无冲突结果发布到线上，验证后同步本地与共同版本
npm run sync:content -- --publish

# 验证合并算法
npm run test:content-sync
```

合并以“上次共同版本、本地内容、当前线上内容”为输入：

- 项目按 `slug`、素材与独立画廊项按 `name` 合并，独立字段修改同时保留。
- 新增项目、素材与排序尽可能合并；不兼容的重排、同一字段两种修改、删除与编辑并发产生冲突。
- tags 等没有稳定 ID 的数组作为一个字段处理，不猜测其内部编辑含义。
- 自动画廊封面根据合并后的项目和首页顺序重建，避免派生字段产生假冲突。
- 冲突时退出码为非零，不写入内容或传输媒体；详情在每次运行的 `merge-report.json`。报告含共同、本地、线上值。调整本地对应字段使其与希望保留的线上值一致后重试，或在共同版本未变化的情况下撤回本地冲突修改；不提供默认“本地获胜”。
- 每次运行在 `output/cloudflare/content-sync-*` 保存本地、远端、共同版本及合并结果。发布成功还保存远端验证快照。预览仍需 Cloudflare 读取权限。

## 共同版本

状态保存在 `data/content-sync-base.json`（被现有 Git 忽略规则排除，包含目标 bucket/origin）。只写本地时，基线更新为此次读取的线上快照；未发布的本地编辑仍作为下一次合并的本地修改。发布成功时，基线更新为验证后的合并结果。

旧工作区首次运行可从历史同步目录迁移：只采用 `local-content.json` 与 `remote-after.json` 完全相同的成功发布快照，不采用任意 `remote-before.json`。若无历史且两边内容相同，可直接建立基线。否则停止，并允许显式指定真实共同版本：

```sh
npm run sync:content -- --base /absolute/path/last-shared-content.json --write-local
```

换电脑时连同基线迁移，或使用明确的历史共同版本。不要将最新线上版本当作旧共同版本，否则会错误解释删除与修改。

## 媒体与并发边界

- `/media/` 引用两边都不存在时停止；发布前检查同名文件内容，不一致时停止，禁止覆盖 immutable 媒体。本地合并直接复用已存在的本地文件，不重复请求 CDN。
- 线上独有媒体会下载到本地；本地独有媒体只在 `--publish` 时上传。旧媒体不会被此脚本删除。
- 用 `data/content-sync.lock` 阻止两个同步进程同时运行。异常强制终止后仅在确认旧进程退出时删除锁文件。
- 写内容前重新读取线上并检查本地是否变化，有变化就停止。媒体已传输而内容写入失败时，媒体保留，不自动删除。
- **Wrangler R2 object put 不提供此脚本可用的原子 compare-and-swap。** 发布时需要暂停后台编辑：最后一次检查和写入之间仍有竞态窗口。发布后的校验不能代替原子条件写入。后台多标签页保存本身的版本冲突控制属于单独任务，尚未在本次修改中实现。
- 同样避免在本地合并写回的一瞬间保存后台；脚本会反复检查文件变化，但它与本地后台没有共享事务锁。
- 内容合并不复制代码或 `public/assets`。如果新增素材位于 `public/assets`，需要先确保对应代码/静态资源版本已部署。
